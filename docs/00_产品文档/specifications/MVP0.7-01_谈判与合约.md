# MVP0.7-01 — 谈判与合约（宣战/停战/和约）

> **功能简述：** 战斗阶段谈判停战，结算阶段检查和约到期与效果

## 1. 功能目的

谈判与合约系统是战争/外交体系的核心机制。在双方交战后，根据战斗结果自动生成停战草案（Peace Treaty），经元老院审批后生效或恢复战争状态。此机制确保：

1. 战斗结束后根据胜负自动生成合理的停战条款（赔款额和有效期）
2. 停战草案需经元老院投票表决通过后方可生效
3. 生效的和约在指定回合数内维持停战状态
4. 和约到期后战争恢复为威胁状态，可重新爆发

## 2. 玩家/系统行为

### 2.1 触发时机

停战议和流程跨越多个阶段：
- 战斗阶段（Combat Phase）→ 生成停战草案
- 元老院阶段（Senate Phase）→ 审批停战草案
- 决议阶段（Resolution Phase）→ 检查和约到期

### 2.2 停战草案生成

**不生成草案的条件：** TRIUMPH（凯旋）、DISASTER（灾难）
**生成草案的条件：** VICTORY（胜利）、DEFEAT（失败）、STALEMATE（僵持）

### 2.3 赔款计算公式

```
raw_indemnity = war.strength × 10 + war.duration × 5
VICTORY → +raw_indemnity（敌方赔给我方）
DEFEAT → -raw_indemnity（我方赔给敌方）
STALEMATE → 0（无赔款）
```

### 2.4 和约到期检查

在决议阶段检查所有 TRUCE 状态且草案为 `approved` 的战争，到期后移回威胁列表。
