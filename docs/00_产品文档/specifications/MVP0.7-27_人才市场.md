# MVP0.7-27 — 人才市场（人物招募池）

> **功能简述：** 通过 Curia 实体管理待招募人物池，在广场阶段提供招募功能

## 1. 功能目的

人才市场（Curia）代表罗马广场上的自由人物池。各派系可以在广场阶段通过出价招募人物，这是游戏人物流转的核心机制。

## 2. 核心规则

### 2.1 人物进入 Curia 的途径

| 途径 | 来源 |
|------|------|
| 新生成 | `_generate_new_figures()` |
| 裁员淘汰 | `forum_api.retire_figure()` |

### 2.2 招募结算规则

- 每个人物独立结算，出价最高的派系获胜
- 同价并列时随机选择

### 2.3 派系容量上限

| 派系数 | 每人派系成员上限 |
|--------|----------------|
| 3 个派系 | 6 人 |
| 4 个派系 | 5 人 |
| 6 个派系 | 4 人 |
| 其他 | 5 人（默认） |

> **口径澄清（WP-I，2026-09-26 · 恢复/澄清，非新规则）：** 上表「派系数」= **注册派系数**（对局建立的派系数量）。
> 派系注册表在对局中从不逐条删除，故容量在整个对局内稳定；该表为**产品法**，
> 由代码单一权威 resolver 提供（不依赖配置参数）。

### 2.4 招募空位约束（vacancy-bounded · 恢复既有规则，WP-I 2026-09-26）

派系可提交的**新招募目标数**受其**剩余招募槽位**约束：

```text
物理空位     = max(0, 派系成员上限 − 存活成员数)
剩余招募槽位 = max(0, 物理空位 − 本回合已预留的 distinct 招募目标数)
```

- 同一目标（同一 `figure_id`）的重复出价只占 **1** 个预留槽位；`剩余招募槽位 == 0` 时同目标重提仍被接受（不改变既有同目标语义）。
- `剩余招募槽位 == 0` 时，**新的 distinct 目标**在该回合不可提交（拒绝，不写入 pending）。
- 结算时每派系终态 `存活成员数 ≤ 派系成员上限`（防御性不变量；不引入任何「幸存者/优先级」排序语义）。
- 该约束由单一权威 resolver 统一提供，CLI / 自动模式 / API / GUI / 结算全部收敛同一权威（无第二张容量表）。
