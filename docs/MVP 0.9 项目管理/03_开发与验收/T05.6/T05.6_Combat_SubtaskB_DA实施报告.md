## 3. Changes Made

### B-1: Data-driven Repeater (Issue #5)
**File:** `CombatStage.qml`

**Before:** Fixed 3-slot Repeater with manual index-based war data lookup:
```qml
Repeater {
    model: 3  // Always 3 fixed slots
    delegate: WarCard {
        readonly property var _allWars: sessionStore.combatActiveWars || []
        readonly property var _slotWarData: index < _allWars.length ? _allWars[index] : null
        warData: _slotWarData
        isEmptySlot: _slotWarData === null
        ...
    }
}
```

**After:** Data-driven Repeater using Python-sourced combined list:
```qml
Repeater {
    model: sessionStore.combatAllWarCards || []
    delegate: WarCard {
        warData: modelData
        isEmptySlot: false
        selectable: root.combatStep === "select" && !root.isResolved(modelData.war_id)
        isResolved: root.isResolved(modelData.war_id)
        ...
    }
}
```

**Reason:** Replace hardcoded 3-slot grid with runtime-computed model that includes both active and resolved wars. The Repeater dynamically handles 0, 1, 2, 3, or more wars without fixed slot limits.

### B-2: isWarResolved() uses Python data (Issue #1 continuation)
**File:** `CombatStage.qml`

**Before:**
```qml
function isWarResolved(warId) {
    return root._resolvedWarIds.indexOf(warId) >= 0
}
```

**After:**
```qml
function isWarResolved(warId) {
    var resolved = sessionStore.combatResolvedWarIds || []
    return resolved.indexOf(warId) >= 0
}
```

**Reason:** Migrate from QML-side fallback tracking to Python-side authoritative data source (`combat_api.py` + `session_store.py`). Removes double-source issue described in PM Issue #1.
